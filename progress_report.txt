RESEARCH PROGRESS REPORT: FAULT-TOLERANT AGENTIC CRAWLERS
=========================================================

OVERVIEW
---------------------------------------------------------
This work investigates the deployment of LLM-driven crawler agents in real-world academic repositories. It addresses the gap where traditional scraping fails under real-world constraints (WAFs, rate limits) and where current LLM agents lack persistence and recovery mechanisms. 

The core contribution of this research is a stateful, fault-tolerant LLM-driven crawler that maintains progress and improves yield under real-world constraints.

KEY CONTRIBUTIONS
---------------------------------------------------------
1. State Persistence Module: A fault-tolerant architecture that atomically preserves crawl state, allowing the system to maintain progress and recover from network or API interruptions without data loss.
2. Adaptive Recovery Mechanisms: Implementation of an adaptive backoff mechanism for API rate limits and header-based request simulation to mitigate WAF blocking.
3. Dual-Layer Triage Strategy: A hybrid architecture combining LLM-driven navigation with deterministic MIME-sniffing, demonstrating significant yield improvements on obscure repository architectures.

SYSTEM EVOLUTION & FAILURE ANALYSIS (v1 vs. v1.01)
---------------------------------------------------------
Initial testing identified severe vulnerabilities when exposing LLM agents to production environments. The transition from the baseline (v1) to the revised architecture (v1.01) isolated and resolved these constraints.

[v1 Baseline Constraints - DSpace MIT]
- Status: 100 pages crawled, 0 successful live downloads.
- Failure 1 (WAF Blocking): Persistent HTTP 400 and 403 errors due to AWS/Cloudflare Web Application Firewalls intercepting standard requests.
- Failure 2 (Rate Limits): LLM navigation was halted by frequent HTTP 429 Resource Exhausted errors from the generative AI API.

[v1.01 Architectural Resolutions]
To resolve these failures and restore effective document discovery, the following modules were integrated:
1. Header-Based Request Simulation: Replaced standard request signatures with rotating browser-mimicry headers (User-Agent, Accept, Referer), neutralizing WAF interference.
2. Adaptive Backoff Mechanism: An asynchronous 5-tier exponential backoff schedule (5s to 120s) that allows the navigation agent to absorb API rate limits without failure.
3. Retrospective Extraction (Offline Parser): A recovery system that parsed preserved `html_logs` to extract documents missed during the v1 live crawl.
4. Heuristic MIME-Sniffing: Deployed for the Arxiv benchmark to bypass extension-less URL masking via HTTP HEAD/GET inspection.

[Resulting Impact]
The initial system failed under real-world constraints, yielding 0 documents on the DSpace repository. The proposed v1.01 architecture resolved these failures, recovering 29 documents retrospectively from DSpace and enabling sustained, high-yield discovery on the subsequent Arxiv benchmark.

EVALUATION METRICS & BENCHMARKING
---------------------------------------------------------
The agent was benchmarked across a legacy repository (MIT DSpace) and a modern pre-print server (Arxiv.org).

[1] EX-T (Total Recall) -> Proves discovery capability.
   - Arxiv Benchmark: 168 unique documents discovered across a 100-page crawl volume.
   - DSpace Benchmark: 29 unique documents discovered across a 100-page crawl volume.

[2] NAV-Y (Discovery Density) -> Proves navigation efficiency.
   - Arxiv: 1.68 files discovered per page visited.
   - DSpace: 0.29 files discovered per page visited.

[3] C-TOK (Token Efficiency) -> Proves cost-performance tradeoff.
   - Arxiv: 202,882 total tokens / 168 documents = ~1,207.6 tokens per discovery.
   - DSpace: 168,168 total tokens / 29 documents = ~5,798 tokens per discovery.

[4] FT-REC (Recovery Delay) -> Proves system robustness.
   - System successfully survived simulated manual interrupts and 429 rate limit walls. State loads in <1s, and steady-state throughput resumes within the first page traversal post-restart.

ADVANCED DECISION-ENGINE METRICS (Derived from execution logs)
---------------------------------------------------------
[5] RS (Redundancy Shield) -> 107 duplicate/binary requests blocked.
   - Proves the state-manager and binary guard perfectly preserve API quotas and prevent re-processing during post-crash recovery loops.

[6] FDR (False Discovery Rate) -> 27.1% (32 out of 118 pages).
   - This measures LLM hallucination in navigation. The LLM successfully located pages with documents 73% of the time, proving highly intentional decision-making rather than random "dumb" crawling.

[7] T-Yield (Triage Yield) -> 100% (168/168 files).(for the latest arxiv run)
   - Proves the efficacy of the Dual-Layer architecture: The LLM scouted 100% of the paths, but the deterministic MIME-sniffer executed 100% of the downloads, keeping the LLM entirely isolated from binary hazards.
